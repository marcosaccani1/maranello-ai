# Manufacturing Quality Dataset

## Overview

This directory contains the synthetic manufacturing dataset used by the Maranello AI Data Agent.

The dataset represents production batches generated by a fictional premium automotive manufacturer operating in the Quality & Manufacturing Operations domain.

All data contained in this directory is synthetic and has been created exclusively for educational, demonstration, and portfolio purposes. It does not represent real production data from Ferrari N.V. or any other automotive manufacturer.

The dataset is designed to support:

- manufacturing performance analysis;
- quality monitoring;
- defect analysis;
- supplier quality analysis;
- production trend analysis;
- data cleaning scenarios;
- KPI calculation;
- chart generation;
- natural-language data analysis through the Python Data Agent.

---

## Dataset

The primary dataset is:

```text
manufacturing_quality_data.csv
```

The dataset contains approximately 2,000 production batch records.

Each row represents a manufacturing batch processed by one production line during a specific shift.

## Dataset Schema

| Column | Type | Description |
|---|---|---|
| `batch_id` | string | Unique identifier of the production batch. |
| `production_date` | date | Date on which the batch was produced. |
| `plant` | category | Manufacturing plant associated with the batch. |
| `production_line` | category | Production line responsible for the batch. |
| `vehicle_model` | category | Vehicle model associated with the production batch. |
| `shift` | category | Production shift during which the batch was processed. |
| `units_produced` | integer | Total number of units produced in the batch. |
| `defective_units` | integer | Number of units identified as defective. |
| `defect_category` | category | Predominant defect category detected during inspection. |
| `rework_units` | integer | Number of units requiring rework. |
| `scrap_units` | integer | Number of units permanently discarded. |
| `downtime_minutes` | float | Production line downtime associated with the batch, expressed in minutes. |
| `cycle_time_seconds` | float | Average production cycle time per unit, expressed in seconds. |
| `quality_score` | float | Internal quality indicator ranging from 0 to 100 under normal conditions. |
| `supplier_id` | string | Identifier of the primary supplier associated with the relevant component. |
| `component_category` | category | Main component category associated with the batch. |
| `inspection_status` | category | Result of the quality inspection. |
| `temperature_c` | float | Recorded process or environmental temperature in degrees Celsius. |
| `operator_team` | category | Manufacturing team responsible for the batch. |
| `notes` | string | Optional operational or quality-related annotation. |

## Data Quality Characteristics

The dataset intentionally contains a limited number of data quality issues.

These anomalies are included to test the ability of the Python Data Agent to detect, validate, clean, and analyze imperfect enterprise data.

The intentional anomalies include:

### Missing Values

Missing values may appear in fields such as:

- `quality_score`;
- `supplier_id`;
- `downtime_minutes`;
- `notes`.

### Duplicate Records

A limited number of production batches are intentionally duplicated.

The Data Agent is expected to identify and handle duplicate observations before performing analyses where duplicates could affect the result.

### Inconsistent Categories

Some categorical values intentionally use inconsistent capitalization or formatting.

Examples may include:

```text
Night
night
NIGHT
```

or values containing leading or trailing whitespace.

### Inconsistent Date Formats

A limited subset of production dates may use alternative date representations.

The Data Agent should normalize dates before performing time-based analyses.

### Outliers

Selected numerical observations contain unusually high or low values.

Examples include:

- unusually high downtime;
- abnormal cycle times;
- extreme quality scores.

### Invalid Values

A small number of records may intentionally violate expected business constraints, such as:

```text
quality_score > 100
defective_units > units_produced
```

These cases are designed to test validation and cleaning logic rather than represent legitimate manufacturing conditions.

## Expected Data Cleaning

Before performing analytical operations, the Data Agent should evaluate the dataset and apply appropriate cleaning strategies.

Depending on the requested analysis, these operations may include:

1. detecting duplicate records;
2. normalizing categorical values;
3. parsing and normalizing dates;
4. handling missing values;
5. validating numerical ranges;
6. identifying potential outliers;
7. validating relationships between related fields;
8. documenting relevant cleaning decisions.

Cleaning operations should avoid silently altering valid observations.

## Derived KPIs

The dataset supports the calculation of several manufacturing and quality KPIs.

### Defect Rate

```text
Defect Rate (%) =
(defective_units / units_produced) * 100
```

### Rework Rate

```text
Rework Rate (%) =
(rework_units / units_produced) * 100
```

### Scrap Rate

```text
Scrap Rate (%) =
(scrap_units / units_produced) * 100
```

### Average Quality Score

Average `quality_score` across the selected production scope.

### Total Production

Sum of `units_produced` across the selected period, line, model, shift, or plant.

### Average Downtime

Average `downtime_minutes` across the selected production scope.

### Average Cycle Time

Average `cycle_time_seconds` across the selected production scope.

## Relationship with the Knowledge Base

The dataset contains quantitative operational information.

Business rules, thresholds, escalation procedures, and quality policies are intentionally not encoded directly in the dataset.

These rules are stored separately in the Maranello AI Knowledge Base.

For example, the Data Agent may calculate a production line defect rate, while the Retrieval-Augmented Generation system retrieves the company policy defining whether that rate is acceptable.

This separation enables hybrid questions that require both structured data analysis and document retrieval.

Example:

```text
The defect rate for Line 2 was 3.8% in August.
Is this acceptable according to the company quality policy?
```

Answering this type of question requires both:

```text
Data Agent
    ↓
Calculate actual defect rate

Knowledge Base / RAG
    ↓
Retrieve applicable quality threshold

AI Orchestrator
    ↓
Combine both results into the final response
```

## Dataset Generation

The dataset is synthetically generated using a deterministic generation process.

A fixed random seed is used to guarantee reproducibility.

The generation process is responsible for:

- creating realistic production observations;
- introducing controlled relationships between variables;
- injecting documented data quality issues;
- preserving reproducibility across environments.

The generation script is maintained alongside the dataset tooling.
